# 语料（corpus/）

本目录存放 DeepSuck 的**诈骗话术库**与相关说明，供骗子模拟器、话术分类器、人设提示词和评测使用。第一版（v0.1）只有框架和少量改写示例，后续按 [SOURCES.md](SOURCES.md) 里的公开资源和社区提交逐步扩充。

```
corpus/
├── README.md        本文件：来源、脱敏原则、格式约定
├── SOURCES.md       可复用的公开项目与数据集调研（名称、链接、许可证、能否使用）
├── scripts/         按诈骗类型的话术库（YAML，每类一个文件）
│   ├── impersonate_cs.yaml       冒充客服
│   ├── impersonate_police.yaml   冒充公检法
│   ├── impersonate_boss.yaml     冒充领导熟人
│   ├── pig_butchering.yaml       杀猪盘
│   ├── task_rebate.yaml          刷单返利
│   ├── investment.yaml           投资理财
│   └── loan_credit.yaml          贷款征信
└── tests/           话术库格式与脱敏检查（pytest）
```

人设提示词和真人化后处理在 [`../personas/`](../personas/README.md)。

## 用途限定

- 仅用于**防御性研究、反诈教育和本项目的评测**：训练和评测“拖住”机器人、识别话术、制作反诈宣传材料。
- 不得用于编写、优化或实施诈骗，不得用于骚扰、冒充真实机构或个人。
- 话术内容均为公开反诈宣传中反复出现的套路的概括，不包含任何未公开的新手法；每条都附带“识别要点”，方便直接用于宣传。

## 来源

v0.1 的所有内容由维护者**根据公开反诈宣传材料归纳后重新撰写**，没有逐字摘抄任何来源，也没有使用任何真实通话录音或聊天记录：

- 公安机关、国家反诈中心等公开发布的常见诈骗类型与典型话术概述；
- 本仓库已有的场景与话术标签（`site/assets/core/scenarios.json`、`tactics.json`、`eval/scammer-scripts.json`）；
- 公开研究数据集的**类别划分和流程结构**（如 TeleAntiFraud、CCL2023 电信网络诈骗案件分类的类别体系），只参考结构，不复制样本文本。

后续如果引入外部数据集的样本，必须满足：许可证允许再分发（见 SOURCES.md 的“能否入库”一列），在条目的 `source` 字段写明出处与许可证，并按下面的脱敏原则改写。许可证不允许再分发或仅限非商业用途的数据集，只能在评测脚本里运行时下载，**不入库**。

## 脱敏原则

1. **不收集任何真实个人身份信息**：不收录真实姓名、手机号、银行卡号、身份证号、住址、微信/QQ 号、钱包地址、车牌、单位名称、真实案件编号。
2. **引用一律改写**：任何来自新闻、通报、用户投稿或数据集的句子，都要改写成概括性的表达，不保留可检索的原句；不保留受害人可识别的细节（年龄、职业、地点、金额组合）。
3. **用占位符代替情报**：需要出现账号、号码、链接时一律写占位符，格式为 `{类型}`，例如 `{银行卡}`、`{手机号}`、`{网址}`、`{APP名}`、`{微信号}`、`{钱包地址}`、`{户名}`、`{金额}`、`{机构}`、`{姓氏}`。模拟器在运行时用虚构值填充（参照 `eval/scammer-scripts.json` 的做法）。
4. **数字**：话术中不出现 6 位及以上的连续数字；金额用 `{金额}` 或“几千”“两万”等模糊说法。测试会检查这一点。
5. **机构名**：用泛称（“某电商平台”“市公安局”“某银行”）或 `{机构}`，不点名真实企业的客服热线、网址或 APP。
6. **社区提交**：提交前请自查以上几点；维护者合并前会再跑一次 `pytest corpus` 和人工检查。发现疑似真实信息的条目会直接删除，不做保留。

## 话术库格式（scripts/*.yaml）

每个文件描述一种诈骗类型，字段如下（`corpus/tests/test_scripts.py` 会校验）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 英文标识，与文件名一致 |
| `name` | 是 | 中文名称 |
| `aliases` | 否 | 别名、常见变体 |
| `version` | 是 | 条目版本号 |
| `related.scenario` | 否 | 对应 `site/assets/core/scenarios.json` 的场景 id（没有对应场景时留空） |
| `related.tactics` | 是 | 对应 `site/assets/core/tactics.json` 的话术标签 id 列表 |
| `targets` | 是 | 常见目标人群（概括描述） |
| `summary` | 是 | 一两句话说明套路 |
| `stages` | 是 | 流程阶段列表，按顺序；每个阶段有 `id`、`name`、`goal`、`lines`（改写台词） |
| `keywords` | 是 | 常用词，可直接作为话术分类的候选词 |
| `pressure_tactics` | 是 | 施压手法列表，每项有 `id`、`name`、`desc`、`lines` |
| `intel_exposed` | 是 | 骗子在这一类里通常会暴露的情报类型（`bank`、`phone`、`url`、`app`、`wechat`、`qq`、`wallet`、`name`） |
| `red_flags` | 是 | 给公众的识别要点 |
| `examples` | 是 | 改写的多轮示例对话，每条有 `id`、`turns`（`role` 为 `scammer` 或 `victim`） |
| `source` | 是 | 出处说明；v0.1 统一为“维护者根据公开反诈宣传归纳改写” |

示例对话里 `victim` 一方是普通的、会犹豫的潜在受害人，不是机器人人设；机器人人设的回复风格见 `personas/`。
