# 真人感：打字特征、说话特征与改写对比

“拖住”机器人最常见的露馅方式不是说错话，而是**太工整**：标点规范、没有错字、句句完整、秒回、从不跑题。本文说明本项目怎么给人设加上真人感，分成两条互不混用的通道：

| | 文字打字特征 | 语音说话特征 |
|---|---|---|
| 适用渠道 | 沙盒、短信、微信等文字聊天 | 语音演示、电话（ASR → LLM → TTS） |
| 实现 | `personas/humanize/`（Python，零依赖） | `personas/voice_traits.yaml`（数据），由语音端读取 |
| 有没有错别字 | 有（同音、形近；每百字错字数按真人样本校准，见下文「错字率校准」） | **没有**：文本直接送 TTS，错字只会读错或读怪 |
| 随机性 | 带随机种子与强度参数，结果可复现 | 由语音端自己轮换（如 `voice/backchannel.py` 的“不连续重复”） |

两条通道共用同一套人设（`personas/prompts/*.yaml` 与 `site/assets/core/personas.json`），但任何一条都不应该引用另一条的扰动：语音回复不要经过 `humanize` 的 `typo` / `punct`，文字回复也不需要 `backchannel`。

## 一、文字打字特征

代码在 `personas/humanize/`，用法和参数见 [personas/README.md](../personas/README.md#真人化后处理humanize)。

1. **错别字**：只做“看得懂”的错。按每百字目标密度（`typoPer100`）放错字，不再按“每条上限”随机：常用词和地名优先（权重 地名 4、常用词 3、同音整词 2、单字 1），整词同音误选（已经→以经、转账→转帐）多于单字。**同一场对话里同一个词错法固定**（会话级错字表），被对方指出后也照旧错。形近字（己/已、候/侯）对应手写输入，由 `shapeTypos` 控制。
2. **手写档**：`handwriting=True` 时改用 `handwritingTypoPer100`（老人约每百字 11 个，并加入手写常见形近字）。**默认关闭**，王阿姨、李大爷默认都是聊天档（每百字 2–4 个）。
3. **固定标点风格**：每个人设只用一种 `punctStyle`，`none`（整段不打标点、用空格断开）或 `comma`（只用逗号）；同一人设不混用句号、问号。
4. **一句话拆成几条发**（`split`）：拆开的几条用换行连接，引擎和语音端按多条处理；老人偶尔用玫瑰、点赞、合十、[强] 这类表情代替逗号（`emojiComma`）。
5. **说话习惯**：第三人称自称（阿姨、姐、老头子）、主动报年龄、道歉、“你忙吧”收尾，各有出现概率。
6. **语音输入式断句**（`voice` 模式）、**重复确认**、**跑题**、**方言词**同前；跑题句**不接在配合句后面**（`coop_step / fake_progress / confirm_intel / re_ask` 这几类意图不加跑题）。
7. **禁用文风**：不出“美篇”式抒情成文（“岁月静好”“感恩遇见”之类），不出 yyds、emmm、绝绝子、xswl 等年轻人网络用语；原句池、输出和 `personas/prompts/_common.yaml` 都有测试。

不变量：数字串（号码、卡号、金额含中文大写金额、逐字报号的中文数字如“幺 六 五”、钱包地址、网址）、平台名与情报字段词（微信、卡号、房间号……，含“微 信”）、打码值（`*`）、占位符 `{...}` 的**内部和紧邻前后一个字**不放错字、表情、标点，也不在那里拆条；户名、收款人等字段名后面几个字不改、人名后面的逗号不删，避免把真实信息改错；同一个种子输出完全一致（Python `personas/humanize` 与 JS `site/assets/js/humanize.js` 逐字一致，`tests/fixtures/humanize.json` 做对拍）；强度 0 原样返回；`humanize` 不替代安全守卫，输出仍要过 `guard_output`。

### 错字率校准（2026-10-18 第二版）

目的：错字太多会被骗子当成故意的，太少又太工整。第一版（下面的“历史参照”）只有成文随笔和年轻人网聊语料，老人档定在每百字约 1.1，偏低。第二版改用**公开、脱敏的老年人聊天样本的统计数字**定档：只统计每百字错字数、错字落在哪类词上、标点和拆条习惯，**不保存、不引用任何原句**，样本本身不进仓库。

| 样本类型（公开、脱敏） | 每百字错字（汇总） | 观察到的特征 |
|---|---|---|
| 老人日常聊天（拼音或语音输入） | 约 2.6 | 错字集中在常用词和地名；同一个词在一段对话里错法一致，被指出后照旧；一句话分几条发；整段不打标点或只用逗号；偶尔用表情代逗号 |
| 老人手写输入截图 | 约 11 | 形近字明显增多，常用字也会写错 |
| 老人写的成文（“美篇”类随笔，繁体字不计） | 约 2 | 抒情成文，不像聊天，所以人设禁用这种文风 |

**档位**

| 档位 | 老人（retiree、王阿姨、李大爷） | 中年（mom、shop_owner） | 年轻人（graduate、小林） | 何时生效 |
|---|---|---|---|---|
| 默认（聊天） | 每百字 2–4（王阿姨 3.0，李大爷 2.5） | 约 2 | 约 1 | 默认 |
| 手写 | 每百字 10 以上（11） | 约 6 | 约 3 | 只在 `handwriting=True` 时 |

取值理由：老人默认档取聊天样本的量级（2.6 附近，王阿姨略高、李大爷略低以示区别），手写档取手写截图的量级；中年、年轻人按打字熟练程度递减，年轻人仍保留一点“随手打”的痕迹。**王阿姨默认档不低于每百字 2**。`personas/tests/test_humanize.py` 和 `test_humanize_elderly.py` 检查：老人默认档 2–4、手写档 ≥10，中年 1.5–3，年轻人 0.6–1.8，同词同错、错字集中在常用词和地名、数字串及其两侧不被改动。

对大模型骗子的影响（`eval/llm_scammer.py`，7 场景 × 3 人设 × 2 种子，默认档）：起疑挂断 4.8%（同 2 种子的旧基线 11.9%），泄露率 0；手写档因费用上限只做了估算，没有实跑，见 [EVAL.md](EVAL.md#大模型扮演骗子起疑挂断重测)。

**历史参照（第一版用到的公开资料）**

| 来源（类型） | 规模 | 每百字错字 | 类型 | 备注 |
|---|---|---|---|---|
| 网聊语料研究（《当代修辞学》2018 年，QQ 聊天） | 144 万字、3.5 万个话轮 | 约 0.02（按“0.84% 的话轮有错、每话轮约 41 字、每个出错话轮按 1 处”换算） | 同音约 80% | 公开摘要；用户以年轻人为主、拼音输入，是下限 |
| 澎湃新闻·数字内容生态实验室《网络不规范用字用词现象研究报告》（2023） | 4946.3 万条、706.6 亿字 | 0.0019（0.192 / 万字） | 常见错误六成以上，形近、音近都有 | 自动检出、只统计规范字词表里的错误，且多为已发布的成文内容，远低于聊天 |
| 本项目人工小样本：面向中老年的公开写作平台上，“退休生活”专题下的公开随笔正文 | 10 篇各取正文前约 300 个汉字，共 3,033 个汉字 | **0.53**（16 处） | 同音 13、同音兼形近 2、形近 1（形近约 6–19%）；另有繁体字若干不计 | 只在内存里统计，未保存原文、作者名或链接；标点密度约每百字 11.7 个（成文，比聊天高） |
| 老年人触屏输入实验（International Journal of Human-Computer Interaction：Older Adults’ Text Entry on Smartphones and Tablets，2014，doi:10.1080/10447318.2014.924348；Handwriting on Touch Screens through Fingers and Stylus，2023，doi:10.1080/10447318.2023.2192107；The Influence of Input Method and Chinese Character Complexity on the Elderly…，2024，doi:10.1080/10447318.2023.2301261） | 32 / 72 名被试等 | 摘要未给出可换算的每百字错字率 | 老人手写表现低于年轻人，字越复杂手写越差；2014 年的研究记录到 13 类输入错误 | 只用作方向参考：老人手写输入更容易出错，形近字是手写特有的 |

人工小样本的局限：只有 10 篇、一个人标注；是成文随笔（可能改过、部分用语音输入），不是聊天回复，**更可能低估**聊天里的错字；来自专题推荐页，选样偏向写得认真的作者。没有找到能在不登录的情况下直接看到的中老年**评论区**原文（评论多由脚本加载，相关社区需要登录或有人机验证），所以没有评论样本。建议负责人或用户另做一次人工抽样：从家里长辈的微信聊天里（经本人同意、只记录统计数字）各取 200–300 字，按同样口径数每百字错字数和同音 / 形近比例，再回来调预设。

第一版据此把老人定在每百字约 1.1、中年约 0.8、年轻人约 0.4；第二版按上面的老年聊天样本统计上调到现在的档位。

## 二、语音说话特征

数据在 `personas/voice_traits.yaml`，每个人设一份，覆盖现有的王阿姨、李大爷、小林和 4 个新人设。**这里的所有文本都不含错别字**（测试会用 humanize 的混淆表检查）。

1. **backchannel（短口头语）**：对方说完后先应一声，像反应慢半拍的普通人，同时盖住 LLM + TTS 的首包延迟。每个人设 8–12 条，格式与 `voice/persona.py` 的 `FILLERS[persona_id]` 相同（字符串列表），`personas.voice_traits.fillers()` 返回可直接替换的整张表。王阿姨、李大爷、小林的前 8 条与当前版本一致，只在末尾追加，已合成的缓存音频不会失效。每条不超过 6 个有效字、不含数字。说不说、说哪条仍由 `voice/backchannel.py` 的规则决定（话太短、催促、短追问时不说；连续两轮不重复）。
2. **mishear（听错）**：电话里把关键词听成同音或近音词，再反问一句，例如“验证码”听成“验证马”：“验证马？啥马？你再说一遍。”这是说话层面的“听错”，不是写错字：`heard` 只出现在反问里，作为人设的理解偏差。挑的词都是骗子流程里的关键词（验证码、安全账户、保证金、解冻金……），听错一次就能逼对方重新解释一遍。
3. **speech（语速与口音）**：`rate` 快 / 中 / 慢，`chars_per_sec` 给 TTS 语速参数参考；`dialect_words` 是会自然带出来的方言词；`accent` 与 `accent_desc` 说明是否带口音（目前只作为提示词与选音色的参考，TTS 本身不做口音合成）。
4. **rhythm（节奏）**：`pre_speech_pause` 开口前停顿 短 / 中 / 长及 `pause_ms` 区间（可映射到语音端的 backchannel 或填充音延迟参数）；`chitchat` 扯家常频率 低 / 中 / 高，`chitchat_every_turns` 每隔几轮扯一次，`chitchat_lines` 是可用的话。

| 人设 | 语速 | 口音 | 开口前停顿 | 扯家常 |
|---|---|---|---|---|
| 王阿姨 | 中 | 无 | 中（400–900 ms） | 高 |
| 李大爷 | 慢 | 北方 | 长（900–1600 ms） | 中 |
| 小林 | 快 | 无 | 短（150–450 ms） | 中 |
| 周伯 · 退休老人 | 慢 | 北方 | 长（800–1500 ms） | 高 |
| 小陈妈妈 · 宝妈 | 快 | 无 | 短（200–600 ms） | 中 |
| 小宇 · 刚毕业学生 | 快 | 无 | 短（150–500 ms） | 低 |
| 郑老板 · 个体小老板 | 中 | 西南 | 中（300–800 ms） | 中 |

接入语音端（`voice/` 下的代码本次没有改动）：

```python
from personas.voice_traits import fillers, personas
FILLERS = fillers()                 # 替换 voice/persona.py 中的 FILLERS
personas()["li"]["rhythm"]["pause_ms"]
```

## 三、对比：首页示例对话改写前后

改写前是首页原版的 3 段示例对话（王阿姨、小林、李大爷），从 git 历史（`420a81f` 的 `site/assets/js/hero-chat.js`）取出，固定在 [`corpus/examples/hero_before.json`](../corpus/examples/hero_before.json)。首页之后已换成改写版，生成脚本不再读 `hero-chat.js` 的当前内容，只检查它的 `SCRIPTS` 字段名。改写时换成新人设，骗子和人设两边都重写，再用 `personas.humanize` 以固定种子做真人化。`site/` 下的代码这次没有改。

- 骗子一侧：按 `corpus/scripts/` 对应类型的流程阶段改写（开场亮身份 → 施压/要求保密 → 给出收款信息），只做轻度错别字（强度 0.3，只开 `typo`）。照“剧本”复制粘贴的话术，标点通常是整齐的；
- 真人化不使用刻意错字：网络梗式写法（神马、孩纸、好滴、手鸡）和读起来像另一个词的替换（钱→前）已从混淆表移除（`confusion.DELIBERATE`，测试会检查）；
- 人设一侧：按 `personas/prompts/` 的拖延与诱导手法改写，每段用对应人设的 humanize 预设（周伯 `retiree`、小陈妈妈 `mom`、小宇 `graduate`），“重复确认”复述的是骗子上一句话；
- 情报值沿用原来的虚构打码值（`622202*********3445`、`139****2233` 等），不新增号码；
- 结构严格按 `hero-chat.js` 的 `SCRIPTS`：每段 `title`（「诈骗类型 · 人设名」）、`source`（来源类型；v0.1 话术库全部是根据公开反诈宣传归纳改写，所以填「据公开反诈宣传改写」；`SCRIPTS` 现有代码不读这个字段，加上也不影响播放）、`lines`；每条 `r`（骗子）或 `s`（人设）二选一，可选 `t`（话术标签）、`i`（情报，必须已打码）、`w`（拖住秒数）；每段 4–6 条，每条不超过 40 字（含标点）。超长的句子在改写稿里就拆短或精简，生成脚本会校验，不满足直接报错；
- 生成：`python corpus/examples/build_hero_rewrite.py`，输出 [`corpus/examples/hero_rewrite.json`](../corpus/examples/hero_rewrite.json)。其中的 `after` 与 `SCRIPTS` 同格式，可以直接替换；`--md` 打印下面这一节，`--check` 检查 JSON 是不是最新。测试会校验这一节和 JSON 一致。

主要变化：原来王阿姨“吃速效救心丸”、小林“反诈课 PPT 第三页”这类台词带一点调侃，人设容易露馅，改写后换成更像普通人的拖法（找老花镜、等老公下班、工资没发）；人设每段都有一句主动追问情报（户名、电话、账户）；冒充领导一段原来只有 4 句，改写后补到 6 句，多问出了户名；刷单一段把骗子说出的户名也记入情报；为满足 40 字上限，长句都在改写稿里精简过（如把银行卡和户名、电话分到两条里说）。
