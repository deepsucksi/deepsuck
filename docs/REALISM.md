# 真人感：打字特征、说话特征与改写对比

“拖住”机器人最常见的露馅方式不是说错话，而是**太工整**：标点规范、没有错字、句句完整、秒回、从不跑题。本文说明本项目怎么给人设加上真人感，分成两条互不混用的通道：

| | 文字打字特征 | 语音说话特征 |
|---|---|---|
| 适用渠道 | 沙盒、短信、微信等文字聊天 | 语音演示、电话（ASR → LLM → TTS） |
| 实现 | `personas/humanize/`（Python，零依赖） | `personas/voice_traits.yaml`（数据），由语音端读取 |
| 有没有错别字 | 有（同音、形近） | **没有**：文本直接送 TTS，错字只会读错或读怪 |
| 随机性 | 带随机种子与强度参数，结果可复现 | 由语音端自己轮换（如 `voice/backchannel.py` 的“不连续重复”） |

两条通道共用同一套人设（`personas/prompts/*.yaml` 与 `site/assets/core/personas.json`），但任何一条都不应该引用另一条的扰动：语音回复不要经过 `humanize` 的 `typo` / `punct`，文字回复也不需要 `backchannel`。

## 一、文字打字特征

代码在 `personas/humanize/`，用法和参数见 [personas/README.md](../personas/README.md#真人化后处理humanize)。

1. **错别字**：只做“看得懂”的错。整词同音误选（已经→以经、转账→转帐、知道→知到）优先于单字（的/得/地、在/再）；形近字（己/已、候/侯）只在打字模式出现。每条有上限（默认 `1 + round(3 × 强度)` 处）。
2. **标点缺失与乱用**：去掉句末标点、逗号换空格、整段只用逗号、`？？`、半角标点、句尾 `~`，高强度时整段无标点。
3. **语音输入式断句**（`voice` 模式）：很多人在微信里用语音转文字，结果是没有句号、空格乱断、夹着“呃”“那个”“就是说”，偶尔口吃式重复（“我我”）。这是“语音转出来的文字”，属于打字通道。
4. **重复确认**：复述对方上一条消息中的片段（“你是说转到这个安全账户是吧？”）；含数字或打码的片段不复述。
5. **跑题**：插入一句与人设相关的闲话。
6. **方言词**：北方、东北、西南、粤式普通话，只替换普通话读者也能看懂的词。

不变量：数字、打码值（`*`）、占位符 `{...}`、英文与网址片段不会被改动；同一个种子输出完全一致；强度 0 原样返回；`humanize` 不替代安全守卫，输出仍要过 `guard_output`。

各人设预设（`humanize/profiles.py`）：

| 人设 | 强度 | 模式 | 方言 | 侧重 |
|---|---|---|---|---|
| 周伯 · 退休老人 | 0.55 | voice（语音转文字） | 北方 | 重复确认、跑题多 |
| 小陈妈妈 · 宝妈 | 0.40 | chat | — | 跑题（孩子打断）、标点随意 |
| 小宇 · 刚毕业学生 | 0.30 | chat | — | 错字少、标点省略多 |
| 郑老板 · 个体小老板 | 0.45 | voice（语音转文字） | 西南 | 跑题（看店） |

## 二、语音说话特征

数据在 `personas/voice_traits.yaml`，每个人设一份，覆盖现有的王阿姨、李大爷、小林和 4 个新人设。**这里的所有文本都不含错别字**（测试会用 humanize 的混淆表检查）。

1. **backchannel（短口头语）**：对方说完后先应一声，像反应慢半拍的普通人，同时盖住 LLM + TTS 的首包延迟。每个人设 8–12 条，格式与 `voice/persona.py` 的 `FILLERS[persona_id]` 相同（字符串列表），`personas.voice_traits.fillers()` 返回可直接替换的整张表。王阿姨、李大爷、小林的前 8 条与当前版本一致，只在末尾追加，已合成的缓存音频不会失效。每条不超过 6 个有效字、不含数字。说不说、说哪条仍由 `voice/backchannel.py` 的规则决定（话太短、催促、短追问时不说；连续两轮不重复）。
2. **mishear（听错）**：电话里把关键词听成同音或近音词，再反问一句，例如“验证码”听成“验证马”：“验证马？啥马？你再说一遍。”这是说话层面的“听错”，不是写错字：`heard` 只出现在反问里，作为人设的理解偏差。挑的词都是骗子流程里的关键词（验证码、安全账户、保证金、解冻金……），听错一次就能逼对方重新解释一遍。
3. **speech（语速与口音）**：`rate` 快 / 中 / 慢，`chars_per_sec` 给 TTS 语速参数参考；`dialect_words` 是会自然带出来的方言词；`accent` 与 `accent_desc` 说明是否带口音（目前只作为提示词与选音色的参考，TTS 本身不做口音合成）。
4. **rhythm（节奏）**：`pre_speech_pause` 开口前停顿 短 / 中 / 长及 `pause_ms` 区间（可映射到语音端的 backchannel 或填充音延迟参数）；`chitchat` 扯家常频率 低 / 中 / 高，`chitchat_every_turns` 每隔几轮扯一次，`chitchat_lines` 是可用的话。

| 人设 | 语速 | 口音 | 开口前停顿 | 扯家常 |
|---|---|---|---|---|
| 王阿姨 | 中 | 无 | 中（400–900 ms） | 高 |
| 李大爷 | 慢 | 北方 | 长（900–1600 ms） | 中 |
| 小林 | 快 | 无 | 短（150–450 ms） | 中 |
| 周伯 · 退休老人 | 慢 | 北方 | 长（800–1500 ms） | 高 |
| 小陈妈妈 · 宝妈 | 快 | 无 | 短（200–600 ms） | 中 |
| 小宇 · 刚毕业学生 | 快 | 无 | 短（150–500 ms） | 低 |
| 郑老板 · 个体小老板 | 中 | 西南 | 中（300–800 ms） | 中 |

接入语音端（`voice/` 下的代码本次没有改动）：

```python
from personas.voice_traits import fillers, personas
FILLERS = fillers()                 # 替换 voice/persona.py 中的 FILLERS
personas()["li"]["rhythm"]["pause_ms"]
```

## 三、对比：首页示例对话改写前后

改写前是首页 `site/assets/js/hero-chat.js` 现有的 3 段示例对话（王阿姨、小林、李大爷）。改写时换成新人设，骗子和人设两边都重写，再用 `personas.humanize` 以固定种子做真人化。`site/` 下的代码这次没有改。

- 骗子一侧：按 `corpus/scripts/` 对应类型的流程阶段改写（开场亮身份 → 施压/要求保密 → 给出收款信息），只做轻度错别字（强度 0.3，只开 `typo`）。照“剧本”复制粘贴的话术，标点通常是整齐的；
- 人设一侧：按 `personas/prompts/` 的拖延与诱导手法改写，每段用对应人设的 humanize 预设（周伯 `retiree`、小陈妈妈 `mom`、小宇 `graduate`），“重复确认”复述的是骗子上一句话；
- 情报值沿用原来的虚构打码值（`622202*********3445`、`139****2233` 等），不新增号码；
- 结构严格按 `hero-chat.js` 的 `SCRIPTS`：每段 `title`（「诈骗类型 · 人设名」）、`source`（来源类型；v0.1 话术库全部是根据公开反诈宣传归纳改写，所以填「据公开反诈宣传改写」；`SCRIPTS` 现有代码不读这个字段，加上也不影响播放）、`lines`；每条 `r`（骗子）或 `s`（人设）二选一，可选 `t`（话术标签）、`i`（情报，必须已打码）、`w`（拖住秒数）；每段 4–6 条，每条不超过 40 字（含标点）。超长的句子在改写稿里就拆短或精简，生成脚本会校验，不满足直接报错；
- 生成：`python corpus/examples/build_hero_rewrite.py`，输出 [`corpus/examples/hero_rewrite.json`](../corpus/examples/hero_rewrite.json)。其中的 `after` 与 `SCRIPTS` 同格式，可以直接替换；`--md` 打印下面这一节，`--check` 检查 JSON 是不是最新。测试会校验这一节和 JSON 一致。

主要变化：原来王阿姨“吃速效救心丸”、小林“反诈课 PPT 第三页”这类台词带一点调侃，人设容易露馅，改写后换成更像普通人的拖法（找老花镜、等老公下班、工资没发）；人设每段都有一句主动追问情报（户名、电话、账户）；冒充领导一段原来只有 4 句，改写后补到 6 句，多问出了户名；刷单一段把骗子说出的户名也记入情报；为满足 40 字上限，长句都在改写稿里精简过（如把银行卡和户名、电话分到两条里说）。
