# 0003 先脱敏再存储与展示

状态：已采纳

## 背景

骗子消息里有银行卡号、手机号、姓名、账户等，可能属于受害者或被冒用的第三方。项目公开展示情报、保存通话记录，必须避免泄露个人信息。

## 决策

- 所有展示、导出、日志、落盘的文本必须先经 `redact`（JS `site/assets/js/redact.js`，Python `deepsuck.redact`），只保留 `masked` 值。
- 原文只在内存中用于提取和打码；送入大模型的上下文也是脱敏文本，模型输出再过滤长数字串。
- 情报提交（`deepsuck.intake`）在写盘前做泄露检查，失败则不生成 PR。
- 录音属于原始数据：仅在用户同意时保存，限期自动删除，查询接口需要 token（#5）。

## 后果

- 新增任何展示或存储路径都必须走脱敏，这是代码评审的硬性检查项。
- 情报价值略降（只有尾号等），换来可公开发布。
- 录音是唯一的非脱敏存储，留存周期和访问控制要单独审视。
