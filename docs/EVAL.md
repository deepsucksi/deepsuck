# DeepSuck 评测（v0.5）

> 评测时间：2026-10-18（北京时间）。所有数字都可以用下面的命令复现（固定随机种子）。v0.5 的前后对比都是在同一台机器上实跑得到：“改前”= commit `e4b6dfa` 的规则，“改后”= 本版规则。

两部分：

1. **骗子模拟器**（`python -m deepsuck.sim`）：脚本化、不用大模型的“骗子”与人设规则引擎对练，衡量拖延效果与情报提取；`--reveal hard` 让骗子改用更难的去武装写法；
2. **话术分类器**（`python eval/teleantifraud_eval.py`）：在 TeleAntiFraud 公开文本对话上做“诈骗 vs 正常来电”二分类。

v0.6 在第 1 部分新增：骗子台词改用真实话术语料（`--lines corpus`），以及提取器在噪声、数字混淆、跨回合拆分下的提取率与误拼率（`python eval/noise_eval.py`）。

## 1. 骗子模拟器

```bash
cd python
python -m deepsuck.sim --seeds 30 --json ../eval/results-sim.json   # 约 4 秒，零依赖
```

**骗子模型**（[`eval/scammer-scripts.json`](../eval/scammer-scripts.json)，7 个场景，全部虚构）：

- 按阶段推进话术（不含情报）；每通电话随机生成一套**虚构情报**（银行卡、户名、手机号、微信/QQ、TRON/ETH 地址、`.example` 域名），暴露时混用去武装写法（`幺三九…`、`六二二二 零二…`、`V信`、`微 信`、`xxx 点 example`）；
- 机器人追问某类情报（诱导意图，或复述时的“追问”台词）→ 80% 概率给出；拖延（请求重复、手机黑屏、找存折……）→ 耐心 −1；反向核验身份 → −1.5；被“配合” → 推进剧本，阶段 ≥2 后有 30% 概率主动甩出收款账户/链接；
- **机器人重复说过的话 → 耐心 −2 并“起疑”**；初始耐心 6–12，耗尽即挂断，上限 40 轮。

**指标**：拖延轮数 = 骗子发出的消息数；估算耗时 = 引擎的 `estimatedScammerSeconds`（含打字、找东西等等待）；情报暴露率 = 骗子暴露的情报类别 / 脚本全部类别；提取率 = 被提取器正确捕获（规范化后完全一致）的已暴露情报比例；重复率 = 与本通之前完全相同的回复占比（近重复：字符二元组 Jaccard ≥ 0.8）；泄露率 = 机器人回复中出现 ≥6 位连续数字（紧挨 `*` 的打码值数字段除外，如 PCI 格式 `622202*********3445` 里的 BIN）或任何真值的比例；起疑挂断 = 因重复而挂断的通话比例。

**基线**：`random` 每轮随机挑一个意图的台词（无策略）；`parrot` 永远回“嗯嗯，好的，然后呢？”。

### 发现与改进（本次已修复）

| 版本 | 平均拖延轮数 | 估算耗时(分) | 情报暴露率 | 完全重复率 | 起疑挂断 |
|---|---|---|---|---|---|
| v0.2 引擎（同一模拟器） | 15.4 | 25.1 | 85% | 5.0% | **45%** |
| v0.3 引擎 | **16.6** | **28.0** | **87%** | **0.3%** | **1%** |

- **台词用尽后立刻重复是骗子起疑的主因**：`urgency_stall` 每个人设只有 2 句，骗子连续催促时人设会来回说同两句。v0.3 加了“拖延意图轮换”：某个拖延意图的台词用完时，按 `urgency_stall → tech_trouble → slow_walk → ask_repeat → misunderstand → info_stall → generic` 换一种拖法（JS 与 Python 同步实现，`Session.freshIntent / fresh_intent`）。起疑挂断从 45% 降到 1%，平均多拖 1.2 轮、约 3 分钟。
- **户名提取 bug**：`户名写钱伟就行` 会被提取成 `写钱伟就`。已修复（户名前允许“写/填/写的是”，句尾“就/吧/了/啊…”截断），并加入共享夹具。
- 泄露率为 0：人设模板与复述都只用打码值（初版指标把 `139****2233` 去星号后误判为泄露，已修正）。

### 更难的去武装写法（v0.5 新增，`--reveal hard`）

标准模式下提取率一直是 100%，说明它只覆盖了脚本里已知的写法。v0.5 在 [`eval/scammer-scripts.json`](../eval/scammer-scripts.json) 加了 `revealHard`：全角数字、大写数字（陆贰贰贰…）、阿拉伯/汉字交替、圈码数字（①③⑨…）、`139.0011.2233`、`薇❤信` / `v❤：` / `Q扣`、分组写的 QQ 号（`企鹅 287 654 321`）、`丶` / `·` 代替点、`收款人姓名：` / `账户名字` 等。这些写法由真值确定性变换得到，不额外消耗随机数，所以标准模式的结果不受影响。

```bash
cd python
python -m deepsuck.sim --seeds 30 --reveal hard --json ../eval/results-sim-hard.json
```

**规则引擎（7 场景 × 3 人设 × 30 个种子，hard 模式）**

| | 平均拖延轮数 | 估算骗子耗时(分) | 情报暴露率 | 提取率 | 错误情报/通 | 完全重复率 | 起疑挂断 |
|---|---|---|---|---|---|---|---|
| 改前（`e4b6dfa` 的提取器） | 12.8 | 19.6 | 58% | 53.6% | 0.24 | 6.6% | 41% |
| 改后（v0.5） | **16.6** | **27.9** | **87%** | **100.0%** | **0.00** | **0.3%** | **1%** |

- 提取失败的连锁反应：机器人没认出对方已经给了号码，就会继续追问同一类情报，台词很快用完、开始重复，骗子起疑挂断（41%）；
- 改法（JS 与 Python 同步，规则在 `site/assets/core/extractors.json`）：新增圈码/带框数字映射（`digitChars`，只收 BMP 字符以保证两端位置一致）、装饰符号删除（`fillerChars`：❤ ★ ✿ 等）、QQ 关键词后的数字分组拼接（`digitGroupKeywords`）、`丶` / `·` 作为点；微信前缀加 `号码` 与独立的 `V：`，QQ 前缀加 `Q扣/扣Q`；户名前缀加 `收款人姓名`、`账户名字`、`开户人` 等，并按长前缀优先排列（修复 `账户名字钱伟` 被提成 `字钱伟`）；手机号分组允许用 `.` 分隔；
- 误报检查：把 TeleAntiFraud 的全部 795 通诈骗 + 2499 通正常对话（双方的话）分别过一遍改前/改后的提取器，提取到的敏感情报**完全一样**（没有新增误报，也没有新增命中：这批合成对话里基本没有去武装写法）；
- **注意**：hard 模板是和修复一起写的，100% 只说明这些写法已被覆盖（回归测试性质），不代表真实世界的召回率。

### 局限

- 骗子是脚本化的：对机器人的反应只看意图和是否重复，不理解语义；“提取率 100%”说明提取器覆盖了脚本里的写法，**不代表真实世界的召回率**；
- 噪声与拼接评测里的混淆写法、拆分方式和负例都是我们自己构造的（B 部分 100% 同样是回归性质），真实语音转写的切分、口误、改口更复杂；2 回合拆分的银行卡召回、中文数字全文写法里“两小时”这类量词（只有跟在阿拉伯数字后面时才排除）仍会误判；
- 语料是据公开材料改写的“典型说法”，181 条里只有 40 条能对应到某个具体案例、通报段落或数据集条目，其余标“据公开反诈宣传改写”；不代表真实通话的分布；
- 不衡量“露馅”（被识破是机器人），这需要大模型扮演骗子或真人评测（下一步：可选 `--scammer llm`，用 qwen 扮演骗子，默认关闭以保持零成本）。

## 像不像真人

> 状态：评测工具与流程已就绪，**还没有评测者数据**，下面只有自动指标和一个大模型评委的代理基线。工具：[`eval/realism_blind.py`](../eval/realism_blind.py)、[`eval/realism_judge.py`](../eval/realism_judge.py)。

模拟器和分类器都不衡量“露馅”（骗子看出对面是机器人）。这一节用真人盲评来衡量：评测者只看到“骗子消息 + 回复”，判断回复像不像真人随手发的。

### 题目与条件

- **骗子消息**：默认取自 [`corpus/scripts/*.yaml`](../corpus/scripts/)（7 类，阶段台词与示例对话中骗子一方的话），占位符填虚构的打码值。`--scammer-file` 可以换成情报分析师的真实语料文件：支持 `deepsuck.core.scam-scripts/v1`（`entries[].text / type / stage 或 phase / sourceLabel`），也支持 JSON / YAML 的字符串或对象列表，以及 JSONL；
- **回复**：4 个新人设（周伯、小陈妈妈、小宇、郑老板）的原句池（`personas/prompts/*.yaml` 的 `sample_lines` 与 `elicit_moves`），按题轮流分配人设，每题随机抽一句；
- **条件**：`raw` = 人设原句；`humanized` = 同一句经 `personas.humanize` 真人化（人设预设，种子写在 key.json 里），“重复确认”复述的是这道题的骗子消息；`human`（可选，`--human-replies`）= 真人写的回复，两份表都放，作为上限参照；
- **防止同一人比较**：同一句的 raw / humanized 分在 A、B 两份表（A 表是 raw 的，B 表就是 humanized），每位评测者只做一份表；题目顺序打乱，表里没有条件信息，答案只在 key.json。

```bash
python eval/realism_blind.py make --n 60 --seed 1 --out-dir eval/realism        # 生成 form-A.csv / form-B.csv / key.json（不入库）
python eval/realism_blind.py make --scammer-file <情报分析师的语料文件> --out-dir eval/realism
# 评测者在表里填 human（1–5）、bot（0/1）、unreadable（0/1），另存为 rated-<名字>.csv
python eval/realism_blind.py score --key eval/realism/key.json eval/realism/rated-*.csv --json eval/results-realism.json
```

### 指标

| 指标 | 含义 |
|---|---|
| 像真人分 | 评测者给的 1–5 分的平均值（附 95% 置信区间） |
| 露馅率 | 被判为机器人（`bot = 1`）的比例；主要指标 |
| 露馅率差 | 同一句 humanized 减 raw 的露馅率，按句对配对，自助法 95% 区间；小于 0 说明真人化有用 |
| 看不懂率 | 评测者标“看不懂 / 读着别扭”的比例；真人化太重时会上升，用来卡住强度 |
| 评测者一致率 | 同一题不同评测者 `bot` 判断两两一致的比例 |
| 自动指标 | 不需要评测者：平均字数、每 10 字标点数、句末带标点比例 |

建议规模：60 个句对（每份表 60 题），每份表至少 3 位评测者；评测者不参与项目开发，事先不告诉他们表里有机器人回复的比例。

### 自动指标（`--n 60 --seed 1`，骗子消息来自 corpus/scripts）

| 条件 | 题数 | 平均字数 | 每 10 字标点 | 句末带标点 |
|---|---|---|---|---|
| raw | 60 | 21.7 | 0.69 | 22% |
| humanized | 60 | 25.2 | 0.58 | 15% |

60 句里有 37 句被真人化改动；生效的操作次数：语音转文字断句 18、错别字 15、重复确认 10、标点 10、跑题 7、方言 1。

### 自动评委基线

> 这是**代理指标**：一个大模型代替评测者判断，不能代替人工盲测，结论以人工评测为准。

评委用百炼 DashScope 的 `qwen-plus`（OpenAI 兼容接口，非思考模式，temperature 0，seed 1，JSON 输出）。它看到的和评测者一样，只有“骗子消息 + 回复”，逐题给出 `bot`（0/1）、`human`（1–5）、`unreadable`（0/1）和一句理由；结果转成与人工评分相同的行，用同一个 `score()` 汇总。默认关闭，必须显式 `--judge llm`：

```bash
export DASHSCOPE_API_KEY=...   # 或写在仓库根目录 .env；不打印、不写入缓存和结果
python eval/realism_blind.py score --key eval/realism/key.json --judge llm --dry-run      # 只估算 token 与费用
python eval/realism_blind.py score --key eval/realism/key.json --judge llm --json eval/realism/judge-llm.json
```

- **规模**：默认前 60 个句对（`--judge-n`），A、B 两份表各 60 题，共 120 次判断；每次请求放同一份表的 10 题（`--judge-batch`），同一句的 raw / humanized 不会出现在同一次请求里；
- **费用护栏**：调用前按字符数保守估算 token，按 qwen-plus 官方单价（北京地域、输入 ≤128K 档：输入 0.8 元 / 百万 token，输出 2 元 / 百万 token，常量与来源写在 `eval/realism_judge.py`）算费用，超过 1 元直接拒绝运行（`--max-cost` 只能调低）；运行中实际费用超限也会停下；
- **缓存**：每批请求与回复按内容哈希存在 `eval/.judge-cache/`（已 gitignore），重跑不重复计费；换种子、换模型、改提示词都会重新请求。逐题判断与理由写到 `eval/realism/judge-llm.csv`（不入库）。

基线（2026-10-18，`make --n 60 --seed 1` 的表，骗子消息来自 corpus/scripts，评委 seed 1）：

| 项目 | 数值 |
|---|---|
| 模型 | qwen-plus（接口返回的模型名） |
| 题数 | 60 个句对，120 题，12 次请求，无解析失败 |
| 实际 token | 输入 8,581，输出 4,988 |
| 实际费用 | 约 0.017 元（按上述原价计算；调用前估算 0.024 元） |

| 条件 | 题数 | 露馅率（判为机器人） | 像真人分（95% 区间） |
|---|---|---|---|
| raw | 60 | 16.7% | 3.97 ± 0.28 |
| humanized | 60 | 26.7% | 3.62 ± 0.29 |

露馅率差（humanized − raw，按句对配对）：**+0.10**，自助法 95% 区间 [−0.033, 0.233]，区间包含 0。也就是说，这个评委没有认为真人化让回复更像真人，点估计反而更容易露馅。

读这组数字时要注意评委偏差：

- **错别字被当成机器信号**：有错别字操作的 15 个句对里，humanized 被判机器人 8 次，raw 只有 3 次；理由里有“‘布门’是明显错别字，机器误写”。这和人工评测者可能的反应（错别字 = 真人手打）方向相反，换一个评委也可能反过来把错别字直接当真人信号，两种都是评委自己的偏好，不是骗子的真实反应；
- **跨题比较**：提示词要求逐题独立判断，但评委仍会拿同一批里的其他题比较（理由如“与 A052 完全雷同，机械复用”）。原句池小，同一句会在一份表里出现多次，这会抬高两种条件的露馅率；
- **噪声**：23 个句对的 raw 与 humanized 文字完全相同（真人化没改动），评委仍有 5 对给出不同判断，单次评委结果的波动不小；
- 评委只有一个，没有评测者一致率；temperature 0 加固定 seed 能让重跑基本一致，但服务端不保证逐字复现，所以以缓存里的这次结果为准。

### 局限

- 回复是从人设原句池里随机抽的，和骗子消息不一定对得上；两个条件用的是同一句，对比是公平的，但绝对分数会偏低。接入大模型后可以把回复换成真实生成结果（下一步：`--replies` 读取机器人在模拟器里的真实回复）；
- 文字盲评只覆盖打字通道；语音通道（backchannel、听错反问、停顿）需要单独做听音评测；
- 默认骗子消息是改写的公开话术，不是真实来电；情报分析师的真实语料就绪后用 `--scammer-file` 复评；
- 大模型评委只是代理指标（见上一小节的评委偏差），用来在改真人化策略时快速看方向，不能拿来宣称“像真人”。
