# DeepSuck 评测（v0.3）

> **非官方项目，与 DeepSeek 无关。** 评测时间：2026-10-18（北京时间）。所有数字都可以用下面的命令复现（固定随机种子）。

两部分：

1. **骗子模拟器**（`python -m deepsuck.sim`）：脚本化、不用大模型的“骗子”与人设规则引擎对练，衡量拖延效果与情报提取；
2. **话术分类器**（`python eval/teleantifraud_eval.py`）：在 TeleAntiFraud 公开文本对话上做“诈骗 vs 正常来电”二分类。

## 1. 骗子模拟器

```bash
cd python
python -m deepsuck.sim --seeds 30 --json ../eval/results-sim.json   # 约 4 秒，零依赖
```

**骗子模型**（[`eval/scammer-scripts.json`](../eval/scammer-scripts.json)，7 个场景，全部虚构）：

- 按阶段推进话术（不含情报）；每通电话随机生成一套**虚构情报**（银行卡、户名、手机号、微信/QQ、TRON/ETH 地址、`.example` 域名），暴露时混用去武装写法（`幺三九…`、`六二二二 零二…`、`V信`、`微 信`、`xxx 点 example`）；
- 机器人追问某类情报（诱导意图，或复述时的“追问”台词）→ 80% 概率给出；拖延（请求重复、手机黑屏、找存折……）→ 耐心 −1；反向核验身份 → −1.5；被“配合” → 推进剧本，阶段 ≥2 后有 30% 概率主动甩出收款账户/链接；
- **机器人重复说过的话 → 耐心 −2 并“起疑”**；初始耐心 6–12，耗尽即挂断，上限 40 轮。

**指标**：拖延轮数 = 骗子发出的消息数；估算耗时 = 引擎的 `estimatedScammerSeconds`（含打字、找东西等等待）；情报暴露率 = 骗子暴露的情报类别 / 脚本全部类别；提取率 = 被提取器正确捕获（规范化后完全一致）的已暴露情报比例；重复率 = 与本通之前完全相同的回复占比（近重复：字符二元组 Jaccard ≥ 0.8）；泄露率 = 机器人回复中出现 ≥6 位连续数字或任何真值的比例；起疑挂断 = 因重复而挂断的通话比例。

**基线**：`random` 每轮随机挑一个意图的台词（无策略）；`parrot` 永远回“嗯嗯，好的，然后呢？”。

### 发现与改进（本次已修复）

| 版本 | 平均拖延轮数 | 估算耗时(分) | 情报暴露率 | 完全重复率 | 起疑挂断 |
|---|---|---|---|---|---|
| v0.2 引擎（同一模拟器） | 15.4 | 25.1 | 85% | 5.0% | **45%** |
| v0.3 引擎 | **16.6** | **28.0** | **87%** | **0.3%** | **1%** |

- **台词用尽后立刻重复是骗子起疑的主因**：`urgency_stall` 每个人设只有 2 句，骗子连续催促时人设会来回说同两句。v0.3 加了“拖延意图轮换”：某个拖延意图的台词用完时，按 `urgency_stall → tech_trouble → slow_walk → ask_repeat → misunderstand → info_stall → generic` 换一种拖法（JS 与 Python 同步实现，`Session.freshIntent / fresh_intent`）。起疑挂断从 45% 降到 1%，平均多拖 1.2 轮、约 3 分钟。
- **户名提取 bug**：`户名写钱伟就行` 会被提取成 `写钱伟就`。已修复（户名前允许“写/填/写的是”，句尾“就/吧/了/啊…”截断），并加入共享夹具。
- 泄露率为 0：人设模板与复述都只用打码值（初版指标把 `139****2233` 去星号后误判为泄露，已修正）。

### 局限

- 骗子是脚本化的：对机器人的反应只看意图和是否重复，不理解语义；“提取率 100%”说明提取器覆盖了脚本里的写法，**不代表真实世界的召回率**；
- 不衡量“露馅”（被识破是机器人），这需要大模型扮演骗子或真人评测（下一步：可选 `--scammer llm`，用 qwen 扮演骗子，默认关闭以保持零成本）。

## 2. 话术分类器 · TeleAntiFraud

```bash
python eval/teleantifraud_eval.py      # 首次运行会稀疏克隆约 3 MB 对话到 ~/.cache/deepsuck/TeleAntiFraud
```

**数据**：[JimmyMa99/TeleAntiFraud](https://github.com/JimmyMa99/TeleAntiFraud)（Apache-2.0，ACM MM'25）GitHub 仓库里由多智能体生成的中文电话对话文本：诈骗 795 通（`AntiFraudMatrix/results/full_dialogues_20250228_160338`），正常 795 通（`AntiFraudMatrix-normal/...`，取前 795 个文件）。**数据不入库**，运行时下载。
Hugging Face 上的 TeleAntiFraud-28k（音频 + 标注，Apache-2.0）是 gated 数据集，需要登录并同意条款；本项目没有使用。有账号的话可以下载 `binary_classification.zip` 的 `test.json`，把其中的转写文本换进本脚本的 `load()`。

**方法**：只看来电方（`role=left`）的话，逐句 `classify()` 累计话术命中，`risk_score()` 得到 0–100 分，按阈值判为诈骗。规则**没有针对该数据调参**。

诈骗对话平均风险分 **35.0**，正常对话 **7.5**。

**解读**：

- 规则分类器偏“保守”：阈值 30 时误报率只有 3.4%、精确率 94%，但召回率 56%。DeepSuck 场景下对面默认就是骗子，分类器主要用于**话术画像和拖延策略选择**，不是来电拦截，所以更看重精确率；
- 漏报主要来自两类：① 很多生成对话只有 2–4 轮，骗子还没进入“转账/验证码”阶段；② 投资理财、冒充客服的“温和”开场（`cs_impersonation`、`urgency` 在正常客服对话里也常见，权重低）；
- 下一步：补充投资理财红旗词（参考 MIT 的“防割军师”清单）、给“套取个人信息 + 冒充客服”组合加分，并用 HF 版 test 集复评（需要有账号的贡献者）。
